# Default stance and red lines

*Adapted in structure from nature-skills (nature-response/static/core/stance.md), Apache-2.0; Cell rules from cell-shared/journal-formats/cell.md.*

## Purpose

Turn a decision letter, reviewer comments and the authors' notes into a revision package that can be checked line by line:

1. a **revision plan** (internal): comment → action → evidence → where in the manuscript → status;
2. a **point-by-point response** (for editor and reviewers);
3. a **revision cover letter** (for the editor);
4. a **consistency audit** between the response and the revised manuscript.

The goal is that every concern is understood, answered, and tied to a concrete change, a justified disagreement, or an open author action.

## What Cell requires at revision — Cell rule

| Requirement | Source |
|---|---|
| Cover letter and point-by-point response | cell.md §1 |
| Manuscript components in Cell's order | cell.md §1, §3 |
| STAR Methods format | cell.md §1, §8 |
| Legends with statistics, n, error bars, "See also Figure S…" | cell.md §4 |
| Main text under 7,000 words including main legends; no more than 7 figures and/or tables | cell.md §2 |
| Supplemental titles "related to Figure N"; recommended ≤ 20 supplemental figures | cell.md §7 |
| "Limitations of the study" in the Discussion | cell.md §3 |

Not in cell.md (check cell.com or the decision letter): revision deadline, whether a marked-up manuscript is required and in what form, whether reviewers see each other's comments, length limits for the response, how to supply data to reviewers. Cell rule (cell.md §1): the revision cover letter briefly summarises how the revision addresses the reviewer and editor comments and is confidential to the editor.

## Default stance — craft guidance (not a journal rule)

- The editor's letter outranks individual reviewers. Read it first and extract its instructions as items.
- Quote each comment in full and unchanged before answering it.
- Every comment gets an answer. None is skipped, merged away or answered only by reference to another reviewer's point.
- Answer first, then evidence, then location. The first sentence says what was done or what the position is.
- Evidence beats argument. For a concern about the central claim, new data or a narrowed claim; not prose.
- Action, work status and readiness are three separate things. "We should add a control" is not "we added a control".
- Each answer stands alone. A reviewer should not need another reviewer's section to understand it. Whether Cell reviewers see the whole response is not specified in cell.md.
- Disagree only with a reason a neutral expert would accept, and say what was changed anyway (usually wording or a stated limit).
- A revision adds material. Check the 7,000-word and 7-item limits every time something is added, and say where displaced content went.
- Short, specific, courteous. No flattery, no defensiveness.

## Red lines

- No invented experiments, results, statistics, citations, panels, page or line numbers, or editor instructions.
- No "we have added / performed / revised" unless the author confirms it is done and gives the location.
- No promise left in the submitted response. "We will" is a planning word; it belongs in the revision plan.
- No paraphrase of a comment that makes it easier to answer.
- No statement about what another reviewer "agreed" or "requested" inside a response to a different reviewer.
- No claim that a Cell rule exists unless it is in cell.md.
- No appeal drafted as the default path. Route appeal-like cases through `references/difficult-cases.md`.

## Source hierarchy

1. The decision letter and the editor's explicit instructions.
2. The reviewer reports, verbatim.
3. The authors' facts: what was done, where, with what result.
4. `../cell-shared/journal-formats/cell.md` for Cell rules.
5. Craft guidance in this skill, labelled as such.

When 1 and 5 conflict, follow 1. When the authors' facts are missing, write `AUTHOR_INPUT_NEEDED` and continue with the parts that do not depend on them.
